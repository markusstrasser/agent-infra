**Verdict:** On frontier agents, compaction at a moderate threshold usually matches full context and can beat it. The weak spot is how today's harnesses compact, not whether they compact. LLM summarization was the weakest quality arm in three of the read papers. It also makes the agent stop re-reading sources, because a plausible paraphrase satisfies it (CliffCompaction, 2609.26779). Recurrent compression lowers run-to-run reliability before it lowers solvability, and the harm sits at a few compaction events (PAIR, 2609.36526, GPT-5.6 Luna). The one controlled wipe test (Beyond Final Scores, 2608.13417) erased context and notes but kept the solution. The next commit was worse for 6 of 7 frontier models (+0.036 for Opus 4.7 up to +0.145). So the right reset is a fresh context plus a short self-written handoff, never an empty one. Carried reasoning is mostly dead weight once its conclusions are written to files. Deleting all past thinking did not hurt and cut tokens 63% (ICLR, 2609.29875, DeepSeek-V4-Flash only, noisy). No lab published a measured result in the window. OpenAI's Codex `new_context` mode (0.153.4, about 2026-09-07) has community posts but no numbers.

## Per-paper notes (FT/PT reads)

**PAIR (2609.36526).** The useful result is the method. To judge a compaction policy, restore the environment at a compaction boundary, continue from both the pre- and post-compression context, and compare. Trajectory-level postmortems mislead: most compressions before a failure were neutral, and harmful compressions also occurred in successful runs. Budgets were set to force 2–3 compactions on short tasks (uncompressed peak ≈12.5K tokens), so the magnitudes do not transfer to 500K windows. The reliability-first framing does transfer: score Pass^k, not Pass@k.

**CliffCompaction (2609.26779).** It has three rules: compact only at a threshold, so the cache stays valid between compactions; keep verbatim fragments and drop tool output over 500 characters; and discard the previous compacted block instead of nesting it. Appendix C.1 has the mechanism claim with the most transfer value. Summarization replaces missing content with "a plausible natural-language paraphrase, which appears to satisfy the agent and discourages it from returning to the ground-truth source". Drop-style methods leave visible gaps, and the agent re-reads. Caveats: Table 6 labels models K2.7/GLM 5.2 while the text says K2.6/GLM 5.1. No Claude or GPT model was the agent under the method. The KernelBench table shows no seeds.

**Beyond Final Scores (2608.13417).** It measures one commit after the wipe, not whole-run outcomes. It does not contradict Fork-and-Flush (2610.07447): F&F measures basin escape over a run with the workspace kept, while this measures the exploitation cost of losing notes. Failure cases ran both ways. Carried state sometimes preserved "a premature or misleading conclusion, or anchor[ed] the agent to a local optimum", and a Gemini lesson became a cached-digest cheat.

**Meta-reasoning (2609.38147).** This is the frontier evidence that a controller over compact state plus on-demand memory scales past where a full-history controller plateaus. The authors' own limits apply: there is no component attribution, the budget is counted in calls and they "draw no inferences at token or runtime levels", and below about 400 calls the design loses.

**ICLR (2609.29875).** It used a single open model and showed large domain swings in every arm, so read it for direction only. Interventions: keeping only the latest reasoning preserved the full-history score (0.872); deleting only the latest dropped it to 0.760; once code was on disk, clearing earlier reasoning left the score unchanged.

**Subagents vs skills (2609.09233).** Subagent isolation pays only when the handoff is a typed contract. Untyped knowledge belongs in context.

## What transfers to our harness

1. **Claude Code compaction settings** (current state: `autoCompactWindow`, ≈50% of the window, PreCompact stdout becomes the summarizer's `customInstructions`; see the `compact-is-headless-scriptable` memory). Nothing here argues for compacting later. CliffCompaction and the harness study both find moderate thresholds safe or better, so keep ≈50%. Two cheap changes follow from the evidence:
   - (a) Extend the PreCompact `customInstructions` so the summary does not paraphrase file contents. It should list the files and sources the next turn must re-read, and state that it is lossy. This targets the re-read suppression in CliffCompaction App. C.1 directly.
   - (b) Probe whether CC folds the prior summary into each new summary (the summary-of-summaries chain that CliffCompaction removes). Run `--debug-file` on a session with two or more auto-compactions and diff the second summary against the first. If it nests, the goal-run ritual's handoff file should be the durable carrier, not the summary.
2. **/loop ticks and wakeup-cadence escalation.** Combine 2608.13417 with F&F and SLA (sibling memo `2026-10-13-idea-basins-fork-flush-related-work.md`): a fresh-context tick is right, but it must start from a short self-written handoff (objective, decisions, dead ends, exact next action), not an empty context and not the transcript. Self-written lessons beat raw workspace access and beat another model's lessons. So the tick that did the work writes the handoff, not the parent. The existing `stale_count ≥2 → change a frame` escalation is where a full flush belongs, with the handoff kept and the "current best idea" line deleted. Do not flush on a fixed schedule.
3. **Judging any compaction or tick-design change.** Score Pass^k (all k runs succeed) and steps, not best-of-k, because compression shows up first as lost reliability (PAIR). Report tokens per arm (eval-token-costs rule); several papers above report only calls.
4. **Carried reasoning.** Opus 5.5 thinking blocks persist and we cannot drop them selectively. The lever we do control is externalizing conclusions to files early: ICLR's risk falls from 67% to 36% once state is externalized. That favors frequent small memo and checkpoint appends (already the researcher stub-first rule) over long in-head reasoning before a compaction.
5. **Shared skills and subagent dispatch.** Dispatch a skill as a subagent only when it has an input/output contract (our result-file plus `**Verdict:**` contract qualifies). Keep reference-style skills in context (2609.09233). The parent should hold a compact state and read results from files rather than replay transcripts (2609.38147), which is consistent with the current subagent_usage rule. Nothing here argues for more subagents per se: total tokens rise.

## Update 2026-10-15 — delta scan and actions taken

No new arXiv work on compaction quality between 2026-10-08 and 2026-10-15 (Exa, arXiv domain; FlowState already excluded above). The new facts come from Claude Code itself (CHANGELOG, 2.1.300 binary strings):

- **Idle compaction (2.1.299).** A conversation over 200K tokens that sits idle about 54 minutes is compacted before the one-hour cache expires. It reaches PreCompact hooks as `trigger:"auto"` (the hook schema enum is still manual/auto). It is tuned with `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` or turned off with `"idleCompaction": false`. With a 500K window, idle sessions now compact below the configured threshold.
- **Per-model window (2.1.288).** `/autocompact` writes `modelSettings.<model>.autoCompactWindow`, which replaces the top-level key for that model.
- **Hook outputs combine.** Several PreCompact hooks' stdout are joined with newlines into `newCustomInstructions`, so more than one hook can contribute summarizer instructions.
- **Nested summaries (action b): answered, yes.** Each summary is written from a context that already contains the previous one, and consecutive summaries share only 4–32% of their 12-word sequences (6 sessions, one with 50 compactions). Details get re-paraphrased at every step instead of carried forward.

Actions: (a) shipped as skills@75b3b83. Every session's summary now opens with a line saying it is lossy, lists the files to re-read, separates verified from unverified work, and carries the previous summary's open items forward word for word. skills@24e41e9 makes the wrap-up hook read the per-model window. skills@871d544 adds `observe/scripts/compaction_boundaries.py` with a pre-contract baseline: 237 boundaries over 7 days, carry-over median 0.099, re-read median 0.5. Re-run it after about a week of contract boundaries and compare the two arms.
