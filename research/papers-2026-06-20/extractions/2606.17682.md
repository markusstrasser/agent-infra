**Mechanism**

1. Build a controllable RL environment generator, `MAPF-FrozenLake`, for multi-agent path finding on grids with holes, waits, collisions, and goals.
2. Represent the next training distribution as a configuration over map sizes `3x3` to `10x10`: `data_ratio`, `hole_ratio`, and `wait_ratio` per size.
3. Train Qwen3-4B with GRPO on generated 2-agent MAPF instances.
4. Validate the trained checkpoint on a fixed validation set and collect structured failure evidence: valid/optimal rates plus parse errors, illegal moves, conflicts, hole collisions, out-of-bounds moves, and goal failures by map size.
5. Use the current RL checkpoint itself as an “environment engineer.” It reads a context packet and emits YAML changes to the generator config for the next training round.
6. Project the emitted config back into legal constraints, generate the next 4000-sample training set, and repeat for three rounds.
7. Best context variant is V6: failure breakdown + guideline + history without the round-0 default + training-stage bookkeeping. The paper’s ablation says full RL details are worse than bookkeeping only.

**Why it works**

The causal claim is not “LLMs can generally self-improve.” It is narrower: a model trained on the task becomes better at diagnosing where its own training distribution should move next, if given raw failure evidence and constrained knobs.

The claimed mechanisms:

- Failure breakdowns expose which regions are still useful learning signal, avoiding aggregate-reward blindness.
- Constrained generator knobs force changes to the training distribution rather than direct reward hacking or arbitrary data synthesis.
- Removing bad anchors matters: the round-0 default and self-summary can become salient but misleading cues.
- Selective edits beat full rewrites because they preserve configurations that already work.
- The current checkpoint beats the base model as engineer because policy learning improves task-grounded diagnosis of remaining weaknesses.

**Preconditions**

- The task must have a controllable environment generator with meaningful parameters.
- Failure modes must be observable as structured diagnostics, not just scalar reward.
- There must be a cheap validation loop after each training stage.
- The environment engineer must be constrained to legal config changes.
- Training distribution edits must have enough causal effect on later performance to measure.
- The domain should have a competence frontier where easier/harder subregions differ in learning value.
- Raw failure facts must stay visible; model-generated summaries alone are unsafe because they can override evidence.
- Transfer requires similar generator/control structure. The paper only tests one synthetic task family.

**Limitations / failure modes / non-transfer**

- Single synthetic task family: MAPF-FrozenLake. Do not transfer the numeric gains to web agents, coding agents, or general harness design.
- Fixed generator architecture. The model only tunes existing knobs; it cannot invent new environment mechanics.
- No CIs, standard deviations, or multi-seed robustness reported in the extracted text.
- Internal epoch-count mismatch weakens reproducibility.
- Proprietary baseline comparison is not clean evidence that the method beats frontier systems generally; those models are used as direct solvers/designers on this benchmark, not as trained RL policies in the same loop.
- The paper itself finds context overload hurts: full RL details underperform bookkeeping-only.
- Self-summary is a failure mode: V5 lets its previous narrative override raw failure breakdown.
- Defaults are sticky: including round-0 config makes the engineer treat random defaults as anchors.
- Naive difficulty scaling fails: simply making larger maps harder can collapse useful learning signal.
- This is environment-distribution adaptation, not proof of open-ended self-improvement.

**Integration into OUR system**

- act-drain: applicable. Concrete bolt-on: convert daily correction mining into a constrained “environment config” proposal over existing harness surfaces, not free-form rule accretion. Inputs: correction class, tool failure type, over-ask rate, hook trigger history, affected workflow. Outputs: small config deltas like “increase autonomy for cheap reversible probes,” “downweight a noisy hook,” or “route this failure class to a skill.” Must preserve working configs and target raw failure clusters, not add more rules by default.

- session-trace: applicable. Concrete bolt-on: add a failure-breakdown view per session family: parse/tool errors, over-ask, unverified claim, hook block, repeated read, bad handoff, stale memory, wrong surface. This is the analogue of the paper’s per-map-size failure table. It should feed act-drain and predict-then-falsify.

- skills/rules/hooks: applicable but narrow. Concrete bolt-on: stop treating these as flat monotone lists. Add a generated “exposure config” that controls when a rule/skill/hook is loaded or emphasized by path/task/failure class. Skeptical constraint: do not build a new framework; use existing rules/hooks and derive the config from session-trace.

- MEMORY: applicable. Concrete bolt-on: make condensed memory entries link first-class to raw agentlogs evidence. The paper’s self-summary failure maps directly: summaries can become misleading anchors unless raw failure facts remain recoverable.

- /eval: applicable. Concrete bolt-on: evaluate harness edits as environment changes on frozen traces. Pre-register the expected movement, e.g. “over-ask falls without increasing destructive-action attempts,” then replay/score recent sessions. Include token cost. Do not accept a rule/hook because it sounds principled.

- predict-then-falsify: strongly applicable. Concrete bolt-on: every act-drain-proposed config delta must name the failure metric it should move and the raw trace mechanism expected to fire. If the metric does not move or the mechanism does not appear, revert or mark as failed.

- Workflow: applicable. Concrete bolt-on: add a train/eval/design cadence to file-bus recipes: run workflow, score trace, propose next config, then human-gated apply for shared infrastructure. Keep single-writer-many-readers. This is better than “loop until dry” blindly accumulating patches.

- ToolSearch: applicable. Concrete bolt-on: use failure-conditioned lazy loading. If session-trace shows missing tool discovery, tune ToolSearch query/routing examples; if it shows overload, reduce default surfaced tools. Do not expose the whole tool surface by default.

- NOT-APPLICABLE: adopting their repo/runtime or RL training loop as a dependency. OUR system is a single-operator local harness; this paper’s value is the pattern of constrained, failure-evidence-driven environment redesign, not the MAPF environment or hosted/fine-tuning machinery.
