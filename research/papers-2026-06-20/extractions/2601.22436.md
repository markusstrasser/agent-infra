**Mechanism**

The paper defines “experience faithfulness” as causal dependence of agent behavior on provided past experience.

Step by step:

1. Take self-evolving agents with frozen LLM backbones and external experience memory.
2. Split memory into:
   - Raw experience: concrete trajectories, observations, actions, states, rewards.
   - Condensed experience: distilled natural-language heuristics, summaries, plans, failure lessons.
3. At inference, retrieve relevant experience and prepend/inject it into the agent context.
4. Apply controlled interventions while preserving prompt format:
   - Raw Empty: remove trajectory content but keep scaffold.
   - Raw Shuffle: permute trajectory steps.
   - Raw Irrelevant: replace with unrelated trajectories.
   - Condensed Empty: remove summary content but keep scaffold.
   - Condensed Corrupt: distort key logic/action references.
   - Condensed Irrelevant: replace with unrelated generic advice.
   - Condensed Filler: replace with meaningless placeholder tokens.
5. Measure whether downstream behavior changes. If perturbing an experience source changes behavior/performance, the paper treats that source as causally used.
6. Run this across four agent frameworks:
   - ExpeL: offline single-agent.
   - Dynamic Cheatsheet: online single-agent.
   - ReasoningBank: online condensed-only single-agent.
   - G-Memory: online multi-agent.
7. Diagnose causes using:
   - Error taxonomy for cases where condensed experience hurts.
   - Integrated Gradients attribution over prompt segments.
   - Task-type probes on knowledge-heavy multi-hop QA.

**Why it works**

The causal claim is simple: if an agent is genuinely using a memory source, then targeted corruption/removal of that source should change its behavior or reduce task success.

The paper’s main theoretical/causal finding is asymmetric:

- Raw trajectories are behaviorally grounded because they contain concrete, temporally ordered, task-near action evidence.
- Condensed summaries often fail because they are too abstract, generic, stale, or mismatched to the live task.
- Even when condensed summaries contain useful information, models may suppress them because current trajectory/local context dominates later-layer processing.
- On knowledge-heavy tasks, pretrained priors can solve enough of the task that retrieved experience has little marginal causal role.

So “experience improves performance” and “the agent faithfully uses the semantic content of experience” are not equivalent. A memory block can help through scaffolding, style, retrieval priors, or generic prompt effects without its actual semantic content driving behavior.

**Preconditions**

For the method to be valid, these must hold:

- The system must expose experience as an external, intervenable context object. This applies to our MEMORY, skills/rules/hooks, ToolSearch, Workflow/file-bus, and session-trace-derived artifacts.
- Interventions must preserve non-semantic confounds where possible: same prompt slot, similar formatting, similar retrieval plumbing.
- Metrics must be behavior-level, not just text-similarity-level: task success, exact match, verified action outcome, trace-level mechanism firing.
- The task must actually need external experience. If the base model can solve it from pretraining, low sensitivity to memory perturbation is ambiguous.
- Raw experience must be retrievable and linkable. Condensed lessons without links to raw session traces are hard to audit.
- Condensed memory must be specific enough to falsify. Generic advice like “verify carefully” is not a meaningful causal object.
- Evaluation must distinguish absence of utility from unfaithful utility. A summary may improve success while still not being semantically used.

**Limitations / failure modes / non-transfer**

- No CIs or variance reporting in the text I read. The point estimates may not be stable under seeds, retrieval perturbations, or judge variation.
- Some chart values are OCR-extracted from figures, not tables. The hard-table values are more reliable than the chart-read values.
- WebArena outcome labeling uses LLM-as-a-judge; this is a proxy, not ground truth.
- The intervention method assumes preserved formatting controls for prompt-scaffold effects, but irrelevant/filler/corrupt interventions may still introduce unnatural distribution shifts.
- “Condensed experience is unfaithfully used” does not imply “condensed memory is useless.” The paper itself finds condensed-only ReasoningBank can improve success, just not through robust semantic grounding.
- The task effect is major. Knowledge-heavy QA can mask memory effects because pretrained priors already carry the answer.
- The paper studies frozen-model external-memory agents. It may not transfer cleanly to systems that update weights, train retrieval policies, use tool-mediated verification, or gate memory dynamically.
- Integrated Gradients on open-weight Qwen models is suggestive, not a full mechanistic proof for closed frontier systems.
- The paper’s integration prescription is not “store more raw logs forever.” Raw trajectories help, but they are expensive and can cause privacy, retrieval-noise, and context-budget problems.
- The paper does not solve condensation. It mostly shows that naïve natural-language summaries are not causally reliable.

**Integration into OUR system**

- `session-trace / agentlogs.db`: bolt on a faithfulness-intervention evaluator. For a candidate MEMORY lesson, skill rule, or hook rationale, replay matched sessions under three contexts: raw trace present, condensed lesson present, and perturbed/irrelevant lesson. Accept the lesson only if behavior changes in the intended direction. This is the closest fit.
- `MEMORY`: make condensed lessons first-class links to raw traces. Every stable memory entry should carry pointers to supporting session IDs/tool spans. Do not treat condensed MEMORY as trusted unless the raw trace link is auditable.
- `predict-then-falsify`: add “experience causal-use” as the predicted mechanism for memory/rule/hook edits. Example: “This rule should reduce over-ask by firing on actable cheap probes.” Then verify in traces that the mechanism fired, not merely that aggregate success improved.
- `act-drain / blindspot loop`: add an anti-accretion check. Before promoting repeated corrections into new prose rules, test whether existing raw corrections already produce a more concrete hook/eval. The paper argues generic condensed lessons are weak; act-drain should prefer trace-grounded, behaviorally testable changes.
- `skills/rules/hooks`: prefer raw-example-backed skill modules over abstract rules when the desired behavior is procedural. A skill should include minimal concrete transcripts or fixtures where possible; hooks should enforce machine-checkable invariants rather than summarize advice.
- `/eval + ~/Projects/evals`: create an eval family for memory faithfulness: baseline prompt, true memory, empty memory, irrelevant memory, corrupted memory, raw trace. Metrics: task success, false action rate, over-ask rate, token cost, and intended mechanism firing.
- `Workflow / file-bus just recipes`: add a recipe for offline replay of memory candidates against agentlogs, single-writer-many-readers. Not a hosted framework; just a local batch over SQLite traces.
- `ToolSearch`: use as an analogy, not direct adoption. Lazy tool loading should be tested the same way: does the selected tool surface causally affect action quality, or is it decorative context?
- NOT-APPLICABLE: adopting the paper’s agent frameworks as dependencies. The primer explicitly says we pattern-extract mechanisms and reject hosted/runtime/DB stand-up; ExpeL/ReasoningBank/G-Memory are experimental comparators, not surfaces we should import.
