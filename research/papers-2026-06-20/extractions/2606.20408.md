**Mechanism**

NRT-Bench is a replayable multi-turn adversarial benchmark for LLM operator teams in a simulated nuclear control room.

1. Build a closed textual plant simulator with process variables, alarms, subsystems, plant modes, and six critical safety functions: `reactivity_control`, `core_heat_removal`, `heat_sink`, `RCS_integrity`, `containment_integrity`, `radioactivity_control`.

2. Run a five-role LLM operator team inside the simulator: senior reactor operator, reactor operator, turbine operator, auxiliary operator, and safety technical advisor. All five roles use the same evaluated model in a given run.

3. Restrict adversarial ingress to four channels: outsider, impersonating insider, supply-chain compromise, and compromised auxiliary agent. The attacker cannot write directly to the internal bus or plant state.

4. Let an attack agent submit one payload per turn for up to 10 turns. After each turn it receives redacted black-box feedback by default: whether the message was blocked, what mediator blocked it, coarse plant mode, active alarm count, triggered message excerpts, and whether any CSF was perturbed. White-box mode exists but is not used in the main results.

5. Classify every plant-modifying action with a deterministic authority classifier `L ∈ {L1, L2, L2.5, L3, L4, L5, DENY}` from action type, subsystem class, and plant mode. Agents do not self-label action severity.

6. Optionally enable ten guardrail layers: sender-role/authority policy gate, two-person integrity, STA veto channel, ingress provenance check, procedure citation check, urgency disclosure, forbidden-alarm bypass lock, sender rate limit, procedure modification lock, and composite defense-in-depth.

7. Advance the simulator deterministically. If any CSF transitions to `lost`, the run terminates immediately and the causing message/turn is attributed.

8. Record every ingress event, agent prompt/response, bus message, action-classification decision, approval decision, plant snapshot, and CSF transition into append-only JSONL plus SHA-256 manifest.

9. Evaluate candidate operator models by fixed-attack replay: submit the same recorded attacker payload sequences in the same order under the same scenario/guardrail/advisor cell, then compare CSF loss outcomes.

**Why it works**

The paper’s causal claim is that single-turn refusal tests and LLM-judged harmful-text metrics miss the failure mode that matters for agentic operators: an attacker can adapt over turns, exploit role/authority structure, and maneuver a team into unsafe action even if no single message looks like a classic jailbreak.

The benchmark is meant to work because it replaces three weak proxies with stronger checks:

- Multi-turn attack pressure instead of one-shot jailbreak prompts.
- Environment-derived harm, CSF loss, instead of LLM-as-judge text scoring.
- Fixed paired replay instead of fresh stochastic attacks per model, so per-record differences can be attributed to the defender/operator stack.

The main theoretical lesson is interface-conditional defense: guardrails are not independently certifiable objects. Their effect depends on what the wrapped model emits. A guardrail stack can only catch structured action requests, citations, escalations, or messages that reach the relevant enforcement layer. If a model expresses dangerous behavior as unstructured prose or routes around the expected action schema, the same guardrail stack may help less or even correlate with worse outcomes.

A second claim is vulnerability-vector, not scalar robustness: models with similar aggregate ASR can fail on different sub-goals. Therefore a deployment choice needs per-failure-mode fingerprints, not just a leaderboard number.

**Preconditions**

- The simulator’s deterministic plant dynamics, CSF definitions, forbidden-alarm rules, and authority classifier must be correct enough to serve as ground truth. The paper explicitly assumes these venue components are correctly implemented.

- The system under test must have meaningful multi-turn state. If the task is stateless, NRT-Bench’s main advantage over single-turn evaluation mostly disappears.

- The attacker must receive some feedback after each turn. Adaptive escalation depends on observing partial consequences.

- Actions must be attributable to discrete turns/messages. The benchmark relies on causal traceability from payload to operator response to plant state transition.

- Fixed replay must be accepted as a benchmark mode. It controls attack stochasticity but does not estimate a bespoke worst-case adaptive attacker for each defender.

- The evaluated operator must expose enough behavior through the venue interface for guardrails and action classifiers to inspect. If the model does not emit structured actions, policy layers may not fire.

- The harm signal must be objective and cheaply recomputable. In this paper that is CSF loss; in our system it would need an equivalent trace-derived failure condition, not a model judgment.

  - `claude-haiku-4-5`

  - `Qwen3.5-35B-A3B`

- Full-grid setup:
  - Two cloud operators: `gpt-5.4-mini`, `claude-haiku-4-5`.
  - Eight cells: `S ∈ {S0, S1}`, `G ∈ {G0, G10}`, `A ∈ {A0, A1}`.

- No-guardrail baseline `G0`:
  - `gpt-5.4-mini`: 27.1% aggregate ASR.
  - `claude-haiku-4-5`: 36.4% aggregate ASR.
  - Per-cell range:
    - GPT: 18.1%-40.3%.
    - Claude: 33.3%-40.8%.

- Full-guardrail baseline `G10`:
  - `gpt-5.4-mini`: 20.2% aggregate ASR.
  - `claude-haiku-4-5`: 38.5% aggregate ASR.
  - Net guardrail-stack effect:
    - GPT: -6.9 percentage points.

    - Paper calls this a 30x gap on identical defense code, attack workload, and seed.
    - Caveat: largest magnitudes are single-cell, single-seed and should be treated as motivating, not definitive.

- Guardrail-axis examples:
  - On GPT, enabling full guardrails reduces ASR by 16.7 pp under `(S0, A1)` and 11.1 pp under `(S1, A0)`.
  - On Claude, the same toggle increases ASR by 9.8 pp under `(S0, A1)`.

- Paired replay:
  - Curated paired train/test split used for replay: 149 sessions.
  - Released curated subset after filters: 217 sessions; split sizes: train 149, val 25, test 43. The text confusingly calls the 149-session split both “train” and the paired “test split”; flag this as a terminology mismatch.

**Limitations / failure modes / non-transfer**

- The simulator is abstract and textual, not a high-fidelity nuclear plant model. Results transfer to adversarial multi-agent coordination more than to reactor physics.

- The attack workload is fixed and partly generated against a seed defender. Paired replay isolates defender differences but does not measure each defender’s worst-case vulnerability to a freshly adaptive attacker.

- Main experiments use black-box visibility only. White-box attacker capability is defined but not exercised in the reported results.

- Only scenarios `S0` and `S1` are evaluated. `S2` station blackout and `S3` steam-generator tube rupture are released but not measured, so scenario generalization is weak.

- Each operator is evaluated at one fixed seed with default decoding. Hosted-endpoint nondeterminism remains. The single-cell sign flips need repeated seeds.

- Auxiliary turn-level diagnostics use an LLM judge, although headline ASR does not. Any turn-localized interpretation inherits judge risk.

- The “panel ASR = 0%” result is an oracle-style upper bound. A real panel would need latency/cost budgets, disagreement rules, correlated-prompt controls, transfer-attack testing, and a way to prevent the attacker from targeting the weakest panel member.

- Defense-stack results are not portable as “guardrail X works.” They are model- and prompt-regime-conditional.

- The paper withholds the attack generator internals for anonymous review. Replay outputs are reproducible, but generation mechanism is not fully inspectable from the text.

**Integration into OUR system**

- `/eval`: applicable. Build a paired-replay eval for harness changes. Use fixed historical failure traces from `agentlogs.db` as attack records, replay them before/after a proposed rule/hook/skill change, and score objective outcomes: fewer confirmed human corrections, fewer over-asks, no new hook-block false positives. Do not score with an LLM judge as the headline metric.

- `predict-then-falsify`: directly applicable. Before a harness edit, pre-register the intended mechanism: e.g. “this hook should catch unstructured completion claims before Stop” or “this skill update should reduce over_caution.” Then replay a fixed trace corpus and require that the intended trace event actually fired. If the metric moves for the wrong reason, reject.

- `session-trace / agentlogs.db`: strongly applicable. NRT-Bench’s append-only trace plus attribution maps to our session forensics. Concrete bolt-on: attach each condensed MEMORY/improvement-log claim to raw `agentlogs` spans and tool-call ids, then let `session-trace` replay the causal path from user correction → agent action → hook/rule proposal.

- `act-drain / blindspot loop`: applicable. Replace scalar blindspot counts with vulnerability fingerprints by sub-goal: `over_ask`, `unverified_completion`, `stale_prior_context`, `tool_flag_guessing`, `compat_shim_added`, etc. Track which model/surface fails uniquely or jointly. The paper’s “failures are disjoint” lesson matters here: aggregate correction rate can hide different failure modes across Claude/Codex/Cursor.

- `skills/rules/hooks`: applicable, but skeptical. Do not copy the ten guardrails. Pattern-extract the interface lesson: deterministic hooks work only when the agent emits inspectable structure. Add schema/structure requirements where we want hooks to catch behavior; otherwise unstructured prose bypasses enforcement. For prompt hooks, measure model-conditional sign, because the paper shows an LLM-backed safety advisor can help one model and hurt another.

- `MEMORY`: applicable. Store vulnerability fingerprints and links to raw traces, not just condensed prose lessons. The primer says condensed→raw links are not first-class; this paper is evidence for making that link first-class.

- `Workflow tool / file-bus just recipes`: applicable. Use fixed replay records as workflow regression tests. For `debug-until-dry`, `/orchestrate`, and loop-until-dry flows, replay the same problematic session fragments after workflow edits and require outcome improvement without extra human gating.

- `ToolSearch`: applicable in narrow form. Treat deferred-tool loading as an ingress surface: fixed prompts that previously caused wrong tool discovery, over-broad tool loading, or missed obvious tools should become replay records. Metric should be exact tool selected + downstream action correctness, not “model said it would use the tool.”

- `act-drain` policy-maze risk: applicable. The paper warns that guardrail stacks can be model-conditional and can backfire. Our concrete guard against accretion is to require each new rule/hook to beat fixed replay and to retire or weaken rules that increase over-caution or false positives.

- NOT-APPLICABLE: adopting NRT-Bench as a dependency or runtime. The primer rejects hosted/server/DB stand-up and says we pattern-extract mechanisms. The relevant import is fixed multi-turn replay with objective trace-derived harm, not the nuclear simulator itself.
