**Mechanism**

Engram is a dual-process long-term memory engine.

1. On write, `add(messages)` appends a raw, lossless episode with event time and ingestion time.
2. The hot write path resolves identity, computes a light embedding, and enqueues the episode. No LLM runs on the critical path; claimed target is under 50 ms.
3. An async consolidation path extracts atomic `(subject, predicate, object)` facts from episodes.
4. Facts are written into a typed bi-temporal store with valid time, transaction time, provenance episode IDs, confidence/salience, and `supersedes` links.
5. Contradictions are resolved cheaply first: exact slot match, embedding-similar predicate match, and content subsumption. If a newer contradictory fact is temporally ordered, the old fact is invalidated, not deleted. Ambiguous cases can escalate to an LLM adjudicator.
6. The read path decomposes queries when needed and retrieves through dense semantic search, BM25 lexical search, graph n-hop proximity, recency, and salience.
7. Ranked lists are fused with weighted Reciprocal Rank Fusion, with defaults reported as `wsem=1.0`, `wlex=0.6`, `wgraph=0.8`, `wrec=0.3`, `wsal=0.25`, `kRRF=60`.
8. Retrieval applies an “as-of” temporal filter, abstention gate, deduplication, provenance tagging, and token-budgeted assembly.
9. The headline `engram_lean` context contains conflict-resolved facts, top fused items, raw session chunks, and session summaries. Reported command uses `--chunks 2`, `--topk 15`, `--extract-k 8`, `--summ-k 28`, `--n-summaries 28`.

**Why it works**

The paper’s causal claim is: full-history prompting degrades because long contexts accumulate distractors and models miss or misuse relevant evidence. A smaller, selected, provenance-tagged context can therefore be more accurate, not only cheaper.

The claimed mechanism has two load-bearing parts:

1. Bi-temporal conflict handling improves knowledge-update and temporal questions by making “current value” and “as-of time T” first-class.
2. Hybrid retrieval improves recall because extracted facts alone drop detail; raw chunks recover specificity while facts provide structured, conflict-resolved signal.

The paper explicitly frames this as consistent with “lost in the middle”: relevant evidence may be present in full context but not used correctly.

**Preconditions**

Engram needs:

1. Session histories with reliable dates or event-time metadata.
2. A workload where long histories contain distractors, updates, stale facts, or temporal queries.
3. A consolidation path good enough to extract durable facts without silently corrupting them.
4. Query-time retrieval that includes both structured facts and raw evidence chunks.
5. A judge/eval setup that compares against a real full-context baseline using the same answerer and judge.
6. A local or configured backend for embeddings, extraction, answering, and judging. The paper says offline deterministic fallbacks exist, but benchmark numbers require OpenAI-compatible model endpoints.
7. For transfer to our system: raw logs must remain addressable, and condensed memory must preserve provenance links back to raw episodes.

It is less likely to transfer cleanly where: histories are short, no temporal updates exist, user queries require broad aggregation over many sessions, or preferences/taste are the target rather than factual recall.

**Measured results**

Benchmark: LongMemEvalS, 500 questions. Each question has a haystack of about 50 sessions, about 115k tokens. Official category-specific judge prompts were used.

Models:
Embedder: `BAAI/bge-small-en-v1.5`, local.
Extractor: `doubao-seed-1.6-flash`.
Answerer: `doubao-seed-2.0-pro`.
Judge: `DeepSeek-V3.2`.
These are 2026-era models, not old GPT-3.5/Claude-3-style pre-frontier evidence, but also not a frontier-model generality test. The paper itself flags “one answerer backbone” as a limitation.

Headline:
`engram_lean`: 83.6% accuracy, Wilson 95% CI `[80.1, 86.6]`, average context 9.6k tokens, errors `0/500`.
`full_context`: 73.2% accuracy, Wilson 95% CI `[69.2, 76.9]`, average context 79k tokens, errors `0/500`.
Gain: +10.4 points, about 8x fewer context tokens.
Paired result: Engram correct where baseline missed on 81 questions; baseline correct where Engram missed on 29. McNemar exact `p < 10^-6`. Paired bootstrap 95% CI for gain: `[+6.4, +14.4]` points.

Implied counts:
`engram_lean`: 418/500 correct.
`full_context`: 366/500 correct.
Both correct: 337.
Both wrong: 53.

Variant:
`engram_full`, which prepends facts above full history, scored 83.4%, reported as `416/499` with one errored question. McNemar against `engram_lean`: `p = 0.91`. The paper interprets this as structured facts carrying the gain and full history adding tokens, not correctness.

Per-category `engram_lean`:
single-session-assistant: 92.9%, `n=56`.
knowledge-update: 87.5%, `n=72`.
single-session-user: 87.5%, `n=64`.
abstention: 86.7%, `n=30`.
temporal-reasoning: 81.1%, `n=127`.
multi-session: 79.3%, `n=121`.
single-session-preference: 73.3%, `n=30`.

Latency:
Retrieval claimed sub-second. End-to-end p50 around 60 seconds, dominated by answerer generation, not retrieval.

Skeptical note: the paper reports one full-set run per system, no repeated-run variance, and no controlled full-500 facts-only ablation. The strongest number is paired against the paper’s own harness and logs, not independently reproduced here.

**Limitations / failure modes / non-transfer**

1. One benchmark: LongMemEvalS only. LOCOMO and other benchmarks are future work.
2. One answerer backbone: `doubao-seed-2.0-pro`. Transfer to frontier models, smaller open models, or our live agent mix is not established.
3. Single run: no quantified stochastic run-to-run variance.
4. No controlled component ablation yet. The facts-only-vs-hybrid claim is stated as a development observation, not a full benchmark result.
5. Weakest categories are multi-session aggregation and preference. That matters for our system because many harness questions are about patterns across many sessions, not single fact recall.
6. Fact extraction can lose nuance. The paper’s own fix is to include raw chunks; that argues against adopting a facts-only MEMORY compactor.
7. The conflict policy assumes newer temporally ordered statements supersede older ones. That is often right for jobs, locations, current preferences, and status; it can be wrong for multi-valued facts, cyclical states, plans, and taste.
8. Bi-temporal memory helps factual/temporal recall, not principal-judged taste. It should not be treated as a judge of whether a remembered preference is still what Markus wants.
9. Privacy/security burden rises because a memory store centralizes sensitive cross-session data.
10. The license is AGPL-3.0 plus commercial. Our primer says not to adopt frameworks as deps; this reinforces pattern extraction rather than dependency adoption.
11. The result depends on measurement integrity: full-context must truly receive the whole haystack, judge prompts must match official LongMemEval, and logs must be replayable. Otherwise the apparent gain can be an eval artifact.

**Integration into OUR system**

Best concrete integration: **MEMORY + session-trace / agentlogs.db + predict-then-falsify gate**.

Bolt-on: make condensed MEMORY entries bi-temporal and provenance-linked to raw `agentlogs.db` spans. Today the primer says raw agentlogs exist but the link from condensed to raw is not first-class. Add a memory record shape with `valid_at`, `invalid_at`, `created_at`, `expired_at`, `supersedes`, `source_session_id`, and `source_span/tool_call/message ids`. Do not delete stale lessons; invalidate and supersede them. This directly matches our append-only memory rule and improves “why do we believe this?” traceability.

Second bolt-on: **session-trace / agentlogs.db** hybrid retrieval. For session forensics, retrieve both structured facts/findings and raw transcript chunks. Do not replace transcript replay with facts-only search. The paper’s own mechanism says facts-only loses recall.

Third bolt-on: **act-drain / blindspot loop**. When act-drain mines a correction, store the correction as an episode and its extracted rule/finding as a bi-temporal fact with provenance. If a later correction contradicts it, invalidate the old rule candidate instead of appending another flat lesson. This targets the primer’s measured accretion failure: rules/hooks grow monotonically into a policy maze.

Fourth bolt-on: **skills/rules/hooks**. Add a deterministic drift check for single-source memory invariants: a condensed lesson that claims a current rule must link to the current rule/hook/skill path or be marked stale. This should be a hook or harness check, not another prose convention.

Fifth bolt-on: **/eval + ~/Projects/evals**. Build an internal LongMemEval-shaped eval from agentlogs: questions over prior sessions, expected answers from raw trace, compare full-history replay vs lean hybrid retrieval. Measure accuracy, token cost, abstention, and stale-fact errors. Use a frozen model, same answerer/judge across systems, and committed per-question logs. This is directly aligned with our “harness on a frozen model” thesis.

Sixth bolt-on: **predict-then-falsify**. Before changing MEMORY/session-trace retrieval, preregister: “lean hybrid retrieval should reduce token count by X and improve or preserve answer accuracy on trace questions; stale-current-value errors should fall.” Accept only if trace evidence shows the intended mechanism fired, especially supersession/as-of filtering. Revert if the gain is only prompt wording or judge noise.

Seventh bolt-on: **ToolSearch**. Applicable only as an analogy, not a direct memory adoption. Deferred tools already load lazily by query; the Engram lesson is to include provenance and raw source snippets alongside retrieved tool metadata. Do not build a full bi-temporal KG for ToolSearch unless we observe stale tool-description failures.

NOT-APPLICABLE: **Workflow tool / file-bus just recipes** as a direct memory engine. Workflow needs resume state and single-writer-many-readers discipline, but Engram’s core benchmark is long-term factual recall. A concrete integration would be provenance-linked workflow journals, not adopting Engram’s retrieval stack into orchestration itself.
