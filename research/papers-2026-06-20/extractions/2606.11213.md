**Mechanism**

CWL, Context Window Lifecycle, replaces opaque compaction with structured eviction.

1. The agent annotates work while it proceeds using one `delimiter` tool.
2. It opens and closes typed episodes:
   - `expl`: exploratory episodes that gather information.
   - `act`: action episodes that modify or commit work.
3. On opening an `act` episode, the agent declares dependencies on earlier closed `expl` episodes.
4. The host stores these annotations as a typed DAG:
   - vertices are episodes.
   - edges go from exploratory episodes to action episodes that depended on them.
   - dependencies only reference already-closed episodes, so cycles are impossible.
5. Protected content is excluded from eviction:
   - system prompt, tool definitions, initial user turns, prologue.
   - active unclosed episodes.
   - all user-authored turns.
6. After every turn, token accounting checks whether the active context exceeds budget.
7. If over budget, a deterministic LLM-free eviction policy runs.
8. It considers only closed, non-prologue, inactive episodes whose dependents are already fully evicted.
9. It prefers the oldest eligible `act` episode, because action effects should already be persisted in the environment.
10. If no eligible `act` exists, it chooses the oldest eligible `expl` episode.
11. It strips content in graduated levels:
   - reasoning traces from exploratory episodes.
   - bulk tool outputs such as search results or directory listings.
   - intermediate artifacts such as file reads and bash outputs.
   - full episode removal.
12. After each stripping step, it recounts tokens and stops once the budget is satisfied.
13. If nothing safe remains to evict, it surfaces the inability to meet budget rather than evicting user content.

**Why it works**

The causal claim is: long-horizon context should be compressed according to recoverability and dependency structure, not recency or model-written summaries.

The paper argues that compaction fails because it destroys provenance: tool output led to decision led to action, but a prose summary collapses that causal chain and may hallucinate under pressure. CWL instead keeps a structured record of which exploratory evidence caused which action. Since action effects persist in the environment, action episodes are usually more recoverable than exploratory evidence and can be evicted first. Since dependencies are explicit, exploratory episodes are protected until all dependent action episodes are gone.

The theoretical bet is not “more memory is always better.” It is “bounded live context plus deterministic structural eviction preserves the right working set better than LLM summarization or blind truncation.” The paper also claims a lower stable token ceiling can improve both cost and quality, because it avoids high-context attention degradation and improves cache behavior up to the point where necessary look-back is lost.

**Preconditions**

- The agent must reliably annotate episode boundaries.
- The agent must correctly classify `expl` versus `act`.
- The agent must declare complete dependencies from actions to prior explorations.
- Action effects must be inspectably persisted in the environment; otherwise action episodes are not actually recoverable.
- The host harness must maintain an episode graph and run token accounting every turn.
- The host must be able to remove or mask prior context at sub-episode levels.
- User turns and prologue content must remain protected.
- Work should have separable exploration/action structure. Purely intertwined reasoning or taste work is a weaker fit.
- The paper’s implementation assumes access to harness internals; this does not transfer directly to closed CLIs unless exposed through transcript/session storage or an external workflow layer.

**Measured results**

- Model used: `GPT-5.4` for all experiments. In our current repo context, treat this as pre-current-frontier / release-specific evidence; rates may not transfer to newer frontier models.
- Main benchmark protocol:
  - CWL condition: all tasks run sequentially in one uninterrupted session with CWL active and fixed `80,000` token budget.
  - Baseline: standard per-task isolated sessions with fresh context per task.
  - Important asymmetry: baseline never faces context pressure; CWL does. This is a stress comparison, not leaderboard-equivalent apples-to-apples.

Benchmark accuracy:

- Terminal Bench 2.0:
  - `n = 5`
  - CWL: `68.25%`
  - baseline: `68.40%`
  - task suite: `89` tasks
- SWE Bench Lite:
  - `n = 3`
  - sampled subset: `50` tasks from `300`
  - CWL: `43.00%`
  - baseline: `40.00%`
- Recovery Bench:
  - `n = 3`
  - CWL: `66.80%`
  - baseline: `69.75%`
- LongCLI Bench:
  - `n = 3`
  - CWL: `20.00%`
  - baseline: `20.00%`

Statistical reporting:

- No confidence intervals reported.
- No standard deviations reported.
- Paper says differences are within run-to-run variance, but does not quantify variance.
- Maximum reported benchmark difference is within about `3` percentage points either direction.

Token/cost claims:

- Terminal Bench 2.0 single-session CWL processed over `80 million` tokens.
- Approximate inference cost: `$55` per complete Terminal Bench 2.0 run.
- Observed inference cost reduction relative to uncapped sessions: `20–70%`, depending on task structure.
- Budget ceiling `τ = 80,000` tokens, described as about `30%` of model context window.
- Budgets above `120,000` tokens: sharp inference-cost increase with no accuracy improvement, according to paper.
- Budgets around `50,000` tokens:
  - inference cost reduced by up to `3×` relative to `120k+` baseline.
  - no measurable accuracy degradation.
  - wall-clock time per task increased by up to `2×` due to re-exploration.
- Claimed Pareto range: `τ ∈ [80,000, 120,000]` for evaluated tasks.

Harness optimization numbers, not pure CWL effects:

- Minimal system prompt under `1,000` tokens.
- Claude Code initial prompt estimated at approximately `20,000` tokens.
- Gitignore-aware glob/grep and search instructions claimed to reduce token consumption `3–6×` relative to Codex-style harnesses on equivalent tasks.
- These are confounded with harness design and should not be attributed to CWL alone.

Case study:

- Repositories: Excalidraw, Redis, Linux kernel.
- Task counts:
  - Excalidraw: `3` tasks.
  - Redis: `3` tasks.
  - Linux kernel: `4` tasks.
- Conditions:
  - CWL active, `τ = 80,000`, single session, GPT-5.4.
  - Same harness/model with default compaction instead of CWL.
- Reported inference cost: `23%` lower with CWL.
- Excalidraw and Redis: both strategies completed all tasks.
- Linux kernel:
  - both completed tasks `1–3`.
  - both struggled on task `4`, QEMU boot/validation.
  - CWL got stuck in emulator configuration loop; manual assistance was needed.
  - compaction discarded build/environment context and required re-exploration.
- This case study is qualitative, not controlled benchmark evidence.

**Limitations / failure modes / non-transfer**

- Annotation quality is load-bearing. Wrong `expl`/`act` classification can preserve junk or evict live context.
- Missing dependencies can evict an exploratory episode while an action that relied on it remains visible.
- Dependency granularity is coarse: dependencies attach to whole exploratory episodes, not individual tool calls.
- Current structure assumes a single linear stream; parallel subtasks, branches, and backtracking are only weakly represented by dependency edges.
- The delimiter protocol may itself change model behavior. Paper observed possible rushing, over-exploration, and looping, but could not attribute causally.
- KV-cache effects are ambiguous. Frequent incremental evictions can invalidate prefix cache repeatedly and become net-negative under sustained pressure.
- Reported cost wins are partly entangled with system-prompt minimization and better search tools.
- The main benchmark baseline is isolated fresh sessions, not summarization compaction under equal long-horizon pressure.
- No CIs or variance statistics are reported.
- Small run counts: `n = 5` for Terminal Bench, `n = 3` for others.
- Model-specific: GPT-5.4 behavior and annotation compliance may not transfer to current frontier models or to Claude/Codex/Cursor.
- Hosted/forked harness dependence does not transfer directly into OUR system because we do not run a hosted multi-agent service and do not adopt frameworks as dependencies.

**Integration into OUR system**

- `session-trace / agentlogs.db`: Applicable. Best bolt-on is a derived episode graph over existing transcripts, not a runtime dependency. Add an offline parser that segments turns into `expl`/`act` episodes from tool-call types, user turns, file edits, and command classes; store edges where an action follows cited/read files or search outputs. Use it for forensic replay and “what evidence caused this edit?” queries. Skeptical note: inferred dependencies are weaker than agent-declared dependencies, so label them inferred and do not use them as ground truth.

- `Workflow tool / file-bus just recipes`: Applicable. Add explicit phase manifests to file-bus workflows: each recipe step emits `episode_id`, `type`, `depends_on`, and artifact paths. This is the cleanest local analogue because Workflow already has pipeline boundaries and single-writer-many-readers semantics. Concrete use: `debug-until-dry` and audit/fix/verify pipelines can preserve exploration findings until dependent fixes are committed, then evict or summarize action logs.

- `skills / rules / hooks`: Applicable, but only as light protocol, not full CWL. Add a rule/skill convention for long tasks: before major action, name the exploration artifacts being consumed. Hook candidate: advisory stop hook when a long-running task claims completion but no dependency-bearing evidence artifact or command output is linked. Do not add a hard gate yet; annotation correctness is semantic and false positives would be high.

- `MEMORY`: Applicable. Use CWL’s condensed-to-raw link idea: every durable memory lesson should retain pointers to raw `session-trace` spans or transcript ids. Concrete bolt-on: append-only memory entries include `source_session`, `turn_span`, and `evidence_episode_id`. This directly addresses the primer’s note that condensed-to-raw links are not first-class.

- `act-drain / blindspot loop`: Applicable. Use episode structure to classify corrections by where supervision intervened: bad exploration, bad action, missing dependency, premature eviction/forgetting, over-ask. Concrete bolt-on: act-drain can mine “human correction after action with no linked exploration” as a separate blindspot class. This is especially relevant to current `over_caution=63 / over-ask`: it can distinguish “asked instead of acting despite sufficient exploration” from “asked because dependency evidence was absent.”

- `/eval + ~/Projects/evals`: Applicable and necessary before adopting. Design an eval that compares current compaction/checkpoint behavior versus derived episode preservation on frozen historical agentlogs. Metrics: task success after compaction/resume, redundant re-exploration rate, token cost, wall-clock, and false confidence after missing evidence. Do not use the paper’s `20–70%` or `23%` as expected local savings; treat them as hypothesis priors.

- `predict-then-falsify gate`: Applicable. Pre-register one mechanism before any harness edit: “episode-linked resume reduces redundant file reads after compaction by X% without increasing missed-instruction failures.” Accept only if session-trace shows fewer repeated reads or fewer correction events tied to forgotten context. If accuracy stays flat but re-exploration rises, that is not a clean win.

- `ToolSearch`: Partly applicable. Do not integrate CWL into ToolSearch itself. Better bolt-on: when a deferred tool is loaded, record the query and selected tool as an exploratory episode; later tool calls that depend on it can link back. This helps explain why a tool was chosen. NOT applicable as a context-eviction mechanism.

- `act-drain` policy-maze risk: CWL suggests a useful countermeasure. Instead of adding more flat rules/hooks, represent rules/hooks as dependency-linked interventions: which recurring correction caused this hook, which sessions depend on it, and when it can be retired. Concrete bolt-on: act-drain proposals should include `depends_on_raw_corrections` and `retire_if_not_hit_by`. This maps to the primer’s accretion failure mode.

- NOT-APPLICABLE: adopting `pi-cwl` as a dependency or requiring a hosted/server runtime. The paper’s fork-level mechanism depends on harness internals. OUR system should pattern-extract episode graphs, dependency manifests, and deterministic eviction/replay policy into local traces/workflows, not import the framework.
