**Mechanism**

1. Build a sparse MoE LLM: M2 has 229.9B total parameters, 9.8B activated per token, 62 decoder-only Transformer layers, hidden size 3,072, vocab 200,064, 256 fine-grained experts, top-8 experts per token, sigmoid expert gating, expert-specific bias terms, GQA, RoPE, full attention, and 192K native context.

2. Pre-train on 29.2T tokens: 19.9T constant-phase tokens plus 9.3T decay/context-extension tokens. Context length is progressively extended from 8K to 32K to 192K using code concatenation, long PDFs, and related-document packing.

3. Add Multi-Token Prediction: start with one MTP module during pretraining, then expand to three MTP modules during continued pretraining via weight copying. Freeze the main model briefly while MTP losses stabilize, then jointly train. At inference, MTP drafts tokens and the main model verifies them in one forward pass for speculative decoding.

4. Generate agentic post-training data with executable workspaces and artifact-aligned rewards:
   - SWE pipeline: crawl/filter permissively licensed GitHub PRs, build Docker environments, tag PR type, extract task/reward pairs, validate task/test consistency, augment with bug injection, commit merging, SWE-Test inversion, and code review tasks.
   - AppDev pipeline: experts write meta-queries and prompts, sample concrete app tasks, dedupe with MinHash, reject bad queries with rubric judges, sample trajectories with expert prompts, then deploy apps and verify execution, interaction, and visual quality.
   - Terminal-Gym: transform Stack Overflow terminal scenarios into structured terminal tasks, synthesize Dockerfiles/tests, iteratively repair environments, remove hints, unify tests, and calibrate difficulty using reference solver pass rates.
   - Cowork tracks: deep search, office artifacts, spreadsheets/finance, and slides, each tied to runnable workspaces and artifact-specific verifiers.

5. SFT on interleaved thinking trajectories: train the model to alternate reasoning, tool calls, observations, and revisions within one long trajectory.

6. RL with Forge:
   - Treat the LLM as policy; everything outside generation, including tools, context management, memory, harness control flow, and subagents, is environment.
   - Optimize individual `(state, action)` pairs while propagating reward over full trajectories.
   - Use CISPO with clipped importance sampling and reward-to-go.
   - Use composite rewards: process rewards, wall-clock completion-time reward, and task performance reward.
   - Mix domains during RL: reasoning, coding, agent, and general tasks, with stage-wise changes in mixture, context length, and difficulty.

7. Scale RL infrastructure:
   - Decouple agent side, gateway/data pool middleware, and training/inference side.
   - Support white-box agents that expose context management and black-box/API-only agents that only expose request streams.
   - Use Windowed FIFO scheduling: allow greedy consumption only inside a sliding window over rollout order, preserving rough distribution order while avoiding straggler blocking.
   - Use prefix-tree merging: compute shared long prefixes once across related training samples; then branch into response-specific segments. Claimed zero approximation error and up to 40x training speedup.
   - Use MTP speculative decoding, prefill/decode disaggregation, and global KV cache pooling for rollout throughput.

**Why it works**

The core causal claim is not “small model magic”; it is **large total capacity plus low activated compute plus environment-grounded agent training**.

The paper’s theory is:

1. Sparse MoE gives high representational capacity without paying dense per-token cost. Fine-grained experts increase routing diversity and reduce utilization variance; sigmoid gating avoids softmax zero-sum competition; expert biases improve load balance with less auxiliary-loss dependence.

2. Full attention preserves long-context, multi-hop, retrieval, and agent-task quality better than hybrid SWA at M2 scale. The authors explicitly say standard proxy metrics missed larger-scale degradation, so they choose full attention despite cost.

3. MTP improves training signal and enables speculative decoding. The claimed mechanism is richer next-token supervision during training and faster inference with identical output quality because drafts are verified by the main model.

4. Agent capability comes from training on trajectories whose rewards are grounded in executable or artifact-level verification, not generic chat preference data. This should reduce reward hacking and teach the policy which tool/harness actions lead to accepted artifacts.

5. Forge’s environment boundary lets RL train over arbitrary agent scaffolds: the model learns from the context presented at each completion, while harness behavior remains external state transition. This is especially relevant for black-box agents.

6. Dense process rewards plus speed rewards improve credit assignment in very long agent trajectories where final outcome-only reward is too sparse.

7. Windowed FIFO addresses a specific RL systems failure: greedy rollout consumption overrepresents short/easy tasks early and long/hard tasks late, destabilizing gradients. Windowing trades off throughput against distributional consistency.

8. Prefix-tree merging exploits repeated context prefixes in agent rollouts. If causal attention over the shared prefix is identical, computing it once is mathematically equivalent to recomputing it per sample.

**Preconditions**

1. Massive model-training infrastructure: this is primarily a frontier-model training paper, not directly runnable in our local single-operator harness.

2. Large-scale executable task corpora: GitHub PRs with tests, Docker-buildable repos, app sandboxes, terminal tasks, office workspaces, spreadsheets, slide renderers.

3. Reliable artifact-level verifiers: tests, Playwright interactions, rendered visual scoring, recalculated spreadsheet values, evidence-grounded deep-search checks, and rubric judges where deterministic checks fail.

4. Enough trajectory volume for RL: the paper assumes large rollout batches, long trajectories, and enough diversity that distributional skew from scheduling matters.

5. A request/response boundary around agent completions: black-box support depends on observing the exact context shown to the model and the model’s action at each step.

6. Stable metadata over trajectories: prefix merging needs known shared prefixes and stored metadata to reconstruct per-sample losses.

7. Trustworthy difficulty calibration: Terminal-Gym and other synthesis loops require reference solvers/pass rates; otherwise they risk generating trivial or overfitted tasks.

8. For transfer to OUR system: agentlogs/session-trace must expose enough structured spans to reconstruct state/action/observation episodes. Raw transcript text alone is insufficient for the deeper mechanisms.

**Limitations / failure modes / non-transfer**

1. The paper is vendor-authored and benchmark claims are not independently replicated in the provided text.

2. The provided text is incomplete: it ends mid-Section 7.1 and references a missing Section 8. Therefore benchmark methodology, baseline settings, scaffolds, pass@k details, judge prompts, and confidence intervals are unavailable.

3. Many crucial reward/verifier details are abstract. “Judge-model evidence checking,” “credible feedback signals,” “visual scorer,” and “rubric-based filtering” are described at mechanism level but not enough to audit false-positive rates.

4. AppDev visual/aesthetic verification depends on subjective judges. This does not cleanly transfer to domains where the principal’s taste is the verifier.

5. Deep-search acceptance uses rubric judges for open-ended report-style tasks. That can reduce fabrication, but it is not equivalent to source-grounded deterministic verification.

6. The full-attention conclusion may not transfer to our system. It is a model-architecture training decision at M2 scale, not a local harness design rule.

7. Forge assumes model-training access. OUR system uses subscription dispatch over Claude Code/Codex/Cursor and does not train weights, so CISPO, MTP, MoE routing, KV cache pooling, and prefix-tree training acceleration are mostly not directly applicable.

8. Windowed FIFO is useful only when there is a batch of asynchronous rollouts whose completion order can bias downstream learning or selection. It is not automatically useful for single interactive sessions.

9. Agent-as-a-Verifier can overfit if the task generator and verifier share assumptions, tools, or rubrics. The paper partly addresses this with scaffold perturbation and multiple render/tool libraries, but gives no falsification rates.

10. Terminal-Gym’s Stack Overflow source can produce dated, narrow, or answer-leaky tasks unless the hint removal and unified testing are very strong. The paper claims controls but does not quantify leakage.

11. Speed reward can induce shallow parallelism or premature termination if not gated by correctness. The paper’s formula requires a baseline completion time and a shaping function, but does not specify calibration.

12. Black-box agent training from observed request streams only works if the observed state is exactly what the model saw. Any hidden state, memory side channel, or transcript loss breaks the MDP reconstruction.

**Integration into OUR system**

act-drain: applicable. Add a **Windowed FIFO drain mode** for daily correction mining if the backlog becomes large and heterogeneous. Drain within a sliding window over chronological session order, not purely “fastest/easiest first,” so short obvious corrections do not starve long-horizon failures. Concrete bolt-on: act-drain queue policy with `window_size = 0.3 * batch_size`, plus metrics for age, class mix, and human-correction severity. Skeptical note: only worth adding if act-drain shows skew by easy/short items; otherwise it is premature.

session-trace: strongly applicable. Represent traces as explicit `(state, action, observation, artifact, reward/evidence)` episodes, not just raw transcript replay. Concrete bolt-on: session-trace derived view that maps each assistant completion, tool call, tool output, file diff, test result, hook trigger, and final claim into a trajectory graph. This is the local analog of Forge’s black-box agent stream.

skills/rules/hooks: applicable. Use **artifact-aligned verifier hooks**, not more prose rules. Concrete bolt-on: for frontend/app tasks, require execution + interaction + rendered screenshot checks before completion claims; for research tasks, require evidence-grounded source links and explicit “no CI/N reported” flags when papers omit them. The mechanism should be hooks/tests around outputs, not additional instruction text.

MEMORY: applicable. The primer says condensed-to-raw links are not first-class. Borrow the paper’s “artifact-aligned trajectory” idea: every MEMORY lesson should retain a pointer to raw session-trace spans and the verifying artifact/hook/test. Concrete bolt-on: memory entries include `source_session`, `trace_span_ids`, `correction_type`, `verifier`, and `accepted_artifact`. This is higher value than copying more summary text.

/eval: strongly applicable. Build evals around **environment-grounded rewards** and **predict-then-falsify**, not judge-only scores. Concrete bolt-on: every harness edit eval should define: target behavior, expected trace signature, verifier signal, time/token cost, and disallowed proxy. For example, an over-ask fix only passes if session-trace shows fewer unnecessary user questions without increased unsupported actions.

predict-then-falsify: strongly applicable. The paper’s strongest transferable claim is that accepted trajectories need credible rewards. Concrete bolt-on: before accepting a new rule/hook/skill, pre-register the mechanism that should fire in traces, then falsify against agentlogs. If the claimed mechanism does not appear, revert even if the prose sounds right.

Workflow: applicable. For file-bus just recipes and loop-until-dry, use **mixed-domain queues** and **difficulty-aware scheduling**. Concrete bolt-on: when running debug/review waves, sample across bug classes and difficulty bands in one wave rather than sequentially exhausting the easiest class. This mirrors mixed-domain RL’s anti-forgetting/anti-overfit rationale.

ToolSearch: applicable. The paper’s scaffold-perturbation lesson transfers: do not let agents memorize one tool layout. Concrete bolt-on: evaluate ToolSearch with perturbed tool descriptions/query phrasings and require retrieval of the same canonical tool across variants. Also log when agents bypass ToolSearch and hand-call a stale tool name.
