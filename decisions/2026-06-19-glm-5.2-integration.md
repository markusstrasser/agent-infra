# 2026-06-19: GLM-5.2 (Z.ai) integration — transport, review-cosigner, NOT extraction

## Context
GLM-5.2 launched 2026-06-13 (Z.ai/Zhipu): 1M context, coding-first, claimed to beat
GPT-5.5 on long-horizon coding at ~1/6 cost; a genuinely NEW training lab independent
of Google/OpenAI/Anthropic/Cursor. Operator: "let's integrate" → "eval for
extraction/ingestion" → "implement into the critique workflow and decide … it's a new lab."

## Alternatives considered (transport)
1. **OpenRouter** (`z-ai/glm-5.2`, existing `OPENROUTER_API_KEY`) — zero new credential, live
   today, ~$1.20/$3.20 per Mtok. Chosen.
2. **GLM Coding Plan** (flat ~$3–19/mo, Anthropic-compatible) — cheaper at heavy volume; needs a
   paid subscription + second transport. Deferred (operator picked OpenRouter top-up).
3. **Direct Z.ai metered API** — another key; API was still rolling out at launch. Deferred.

## Counterevidence sought
- *Would GLM beat the incumbent extractors?* Ran it as a screening arm in `extraction_bakeoff`
  against gpt-5.3 (intel) / gemini-3-flash (phenome). Looked specifically for a faithfulness or
  yield edge that would justify a switch — **found none** (all arms 100% byte-exact on phenome;
  GLM lowest yield, highest cost). The "1/6 cost coding model" prior did NOT transfer to
  structured extraction: GLM's heavy default reasoning makes it 1.8× tokens + 2.4–15× latency.
- *Is GLM's `[]` on the diekstra methodology-paper a miss?* No — it matches the only
  contract-faithful arm (Composer); the gold there is contract-violating. Trace-audited.

## Decision
Three-part, by where GLM's properties actually pay off:
1. **Transport — integrated.** llmx `zai` provider routed through OpenRouter (`llmx@ea2e4bf`);
   `llmx chat -m glm-5.2` live, reasoning effort high/xhigh. Flips to direct Z.ai key later.
2. **Critique workflow — added as opt-in 4th-lineage cosigner** (`glm` axis / `glm_review`
   profile, `skills@f5b28fd`). Its value is exactly its NEW-LAB independence — real cross-lab
   adversarial diversity (constitution P12: same-lab panels ≈ 1 effective vote). NOT in any
   default preset; promotion gated on `evals/critique_replay` measurement, same bar as
   cross2/composer. Live-smoked end-to-end + dogfooded on this eval's own design.
3. **Extraction/ingestion — REJECTED (no-change).** Keep gpt-5.3 (intel) / gemini-3-flash
   (phenome); this is the consumer path for substrate's `claimcore` ingest. GLM is
   cost-dominated for high-volume extraction — careful reasoning is wasted on a task whose
   quality ceiling cheap+fast models already hit. (`evals` DECISIONS `glm-5.2-extraction`.)

**Invariant:** GLM-5.2's heavy default reasoning makes it ill-suited to high-throughput
low-reasoning tasks (extraction/ingestion) but well-suited to occasional, thorough,
independent-lab REVIEW. Match the model's reasoning profile to the task's reasoning demand.

## Substrate note
"`/eval` what substrate needs": substrate's active work (claimcore epistemic-status engine,
OVERNIGHT.md) is **deterministic** and already shadow-validated 100% — no model bakeoff needed.
Substrate's one model-eval consumer is `claimcore`'s ingest path, which the extraction screening
above directly serves. GLM-as-`evalcore`-neutral-judge validation is available-but-deferred (a
real consumer — judge-family neutrality when candidates are Google/OpenAI/Anthropic — but not
urgent; the critique dogfood already exercises GLM-as-reviewer).

  supported / 0.605 graded — *as good as or better than* the trusted GPT judge (0.352 / 0.789) on
  the binary call, slightly weaker on graded faithfulness. **Admissible as a neutral cross-lab
  judge family (screening-grade; prefer for binary/detection, pair for fine 0–3 scoring).** See

  timestamp-prefix parse bug that was silently zeroing the opus neutral judge in the shared
