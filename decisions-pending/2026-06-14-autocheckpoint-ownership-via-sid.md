# Stop-hook auto-checkpoint commits OTHER sessions' files via the clobberable current-session-id

**Boundary:** shared (the Stop-hook auto-checkpoint is shared infra — fires in every project, every session)

**Recommendation:** Decide file ownership in the auto-checkpoint **only** from THIS session's own Write/Edit ledger (which the hook already maintains — it correctly *excluded* files "in no session Edit/Write ledger"), and **never** fall back to matching the global `~/.claude/current-session-id`. When concurrent peer sessions share a checkout, `current-session-id` gets clobbered (last-writer-wins), so any file the hook can't resolve via its own ledger must be **left uncommitted**, not attributed to whoever currently owns the sid. (Root *cure* is orthogonal and stronger: launch concurrent sessions with `claude --worktree` so they never share `current-session-id` — but the hook should be correct even when that's skipped.)

**Dissent / risk:** This bug only bites with multiple live sessions on one checkout — a case `claude --worktree` already eliminates, so hardening the hook arguably adds logic for a self-inflicted situation. Counter: it's a *silent correctness* failure (one session commits another's in-flight, possibly mid-edit, work — observed below), it's cheap to fix (the ledger already exists; just remove the sid fallback), and the operator demonstrably runs many concurrent sessions (4 distinct sids this session, 199 claude procs). Low iatrogenic risk: failing-closed (leave unresolved files uncommitted) is strictly safer than the current mis-attribution.

**Open question for you:** harden the hook (remove the sid fallback → fail-closed on unresolved files), or rely solely on worktree-isolation and leave the hook as-is?

**Reversible?** Yes — a localized edit to the auto-checkpoint hook; revert if it over-excludes. Cost-if-wrong: a genuinely-owned file occasionally not auto-committed (the human commits it explicitly) — strictly safer than the current cross-session contamination.

**Evidence:** This session (`53a9f3e3`) — the auto-checkpoint produced two `[wip]` commits sweeping a *peer's* uncommitted work: `730a5f2` (codebase-map.py +14, sid `36c449a4`) and `13d4f696` (codebase-map.py +141/−79 mid-rewrite + CLAUDE.md, sid `45c85753`) — neither sid is mine; `current-session-id` was simultaneously clobbered to a *third* (`9547ab33`). The hook even deferred a file with mtime<90s (a peer actively writing) — so it committed another session's in-flight rewrite. Part of the session-end **principal-by-default** finding (P8 silent-proxy: a clobberable proxy stood in for the actual file author).
